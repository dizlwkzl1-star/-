# 위탁판매 프로젝트 — 실행 인계 문서

> **작성일**: 2026-09-10 · **전제**: 자본은 신용카드 한도뿐, 위탁판매, 정산 빠른 플랫폼만 사용
> **용도**: 기존 코드베이스가 있는 프로젝트로 넘어가 바로 구현을 이어가기 위한 스펙

## 이 문서를 읽는 AI에게

1. **`[미검증]` 표기를 확정 사실로 다루지 말 것.** 이 문서의 수치는 공개 자료로 검증한 것과 논리적으로 도출한 것이 섞여 있다. 후자는 표기돼 있다.
2. **9장(미검증 가정)을 먼저 읽을 것.** 전략 전체가 어떤 가정 위에 서 있는지 거기 있다.
3. **사용자 원칙**: "가설이나 추측으로 답하지 말 것. 데이터로 검증한 것만 말하고, 데이터로 봤을 때 잘못된 부분은 고칠 것."
4. **이 프로젝트에는 이미 동작하는 코드가 있다.** 도매 API 연동, 상품 등록 자동화가 구현돼 있고 실제 등록 이력도 있다. **새로 짜지 말고 기존 코드를 먼저 읽을 것.**

## 0. 한 줄 요약

**카드 신용공여기간(최대 45일)과 플랫폼 정산(D+11~12)의 차이가 무이자 운전자본이 된다. 자기 자본 0으로 돌아가며, 정산금 즉시 선결제로 한도를 회전시키는 것이 이 사업의 핵심 레버다.**

## 2. 현금 구조 (이 사업의 본체)

### 2.1 사이클

| 시점 | 사건 | 현금 |
|---|---|---|
| D+0 | 주문 접수 → 도매에 **카드로 발주** | 0 (아직 안 나감) |
| D+2~3 | 배송 완료 | — |
| D+10 | 구매확정 (배송완료 +7일) | — |
| **D+11~12** | **정산 입금** | **+판매대금** |
| D+15~45 | 카드 결제일 (평균 D+30) | −도매대금 |

**정산이 카드 결제보다 평균 18~19일 먼저 들어온다. CCC가 음수다.**

### 2.2 선결제가 규모를 3.75배로 만든다

```
미결제 카드잔액 = 일 발주액 × 정산 리드타임
카드 결제일은 월 1회 → 가만히 두면 1~1.5개월치가 물림
정산금으로 즉시 선결제 → 12일치만 물림
```

| | 최대 미결제 잔액 | 한도 1,000만원으로 돌릴 수 있는 월 매출 |
|---|---|---|
| 선결제 안 함 | 약 1.5개월치 | 1,332만원 |
| **선결제 운영** | 약 12일치 | **5,000만원** |

선결제하면 **몇 분~1시간 내 한도가 복구**된다.

### 2.3 배송 1일 = 매출 9%

```
일일 발주 가능액 = 카드한도 ÷ 정산 리드타임
정산 리드타임 = 도매 배송일 + 구매확정 대기(7일) + 정산일
```

| 도매 배송 | 리드타임 | 같은 한도로 돌릴 수 있는 규모 |
|---|---|---|
| 3일 | 12일 | 기준 |
| **2일** | 11일 | **+9.1%** |
| **1일** | 10일 | **+20%** |

**마진율 9%를 더 뽑는 것보다 빠른 도매처를 고르는 게 쉽다. 소싱 기준에서 회전이 마진보다 위다.**

### 2.4 이 구조를 깨는 것 3가지

**① 부가세** — 가장 흔한 파산 경로

| | 월 납부세액 (990건 / 판매가 6만 / 공급가 3만 기준) |
|---|---|
| 도매 **세금계산서 수취** | 약 **225만원** |
| 계산서 **미수취** | 약 **540만원** |

**계산서 수취 여부가 세금을 2.4배 가른다.** 카드 결제라도 계산서는 별도다. 도매처 발행 여부를 반드시 확인.

**② 완충 0** — 정산이 하루만 밀려도 선결제할 돈이 없고 → 한도 안 풀림 → 발주 불가 → 매출 정지.
→ **이익의 30%를 완충 계좌로 분리. 완충이 1개월치 도매결제액에 도달하면 전액 재투자로 전환.**

**③ 성공이 리스크** — 갑자기 잘 팔리면 한도가 먼저 막히고, 발주 불가 → 주문 취소 → 플랫폼 페널티.
→ **일일 발주 상한을 시스템에 강제.**

## 3. 플랫폼 — 정산 속도 순

| 순위 | 플랫폼 | 정산 | 수수료 | 비고 |
|---|---|---|---|---|
| **1** | **카카오 톡스토어** | 구매확정 **+1영업일** | **판매수수료 무료** | 총 5만개 / **월 1만개** 등록 한도 |
| **2** | **오늘의집** | **일정산 D+2** | 카테고리별 `[미확인]` | 생활·수납·인테리어 카테고리 적합 |
| **3** | **토스쇼핑** | 구매확정 +2영업일 | 8% / **광고경유 0%** | 이미지에 로고·텍스트 금지 |
| 4 | 네이버 | 빠른정산 | 4.6~6.6% | 신규는 스타트 제로수수료 |
| **제외** | **쿠팡** | 70%/15일 + **30%/60일** | 4~10.9% | **60일이 카드 결제일(45일) 초과 → 자기 돈으로 메워야 함** |

**쿠팡은 볼륨이 커도 이 구조에서 배제한다.**

## 4. 반품 — 네이버 반품안심케어

| 항목 | 내용 |
|---|---|
| 보상 | 귀책사유 무관, 주문건당 **1회**, 교환/반품 배송비 **최대 7,000원** |
| 이용료 | **네이버 전액 지원** (판매자 부담 0) |
| 부가효과 | **'무료교환반품' 태그 노출** → 전환율 상승 |
| **제약** | **도착보장 상품 한정**, 건당 1회, 7,000원 상한(부피·도서산간 초과분 자부담) |

**정확한 손익**: 반품 시 상품 대금은 환불되어 **매출은 0**. 7,000원은 왕복 배송비(약 6,000원)를 커버할 뿐이다.
→ **"반품하면 수익"이 아니라 "반품 배송비 손실이 0에 가깝다"가 맞다.**

배송비를 판매가에 +@로 흡수하고 무료배송·무료반품으로 운영하는 전략은 유효하다.

## 5. 소싱 — 5층 게이트

**순서가 중요하다. 상품이 아니라 공급처를 먼저 거른다.**

### 1층 — 공급처 게이트 (한 번 하면 계속 씀)

| 지표 | 왜 |
|---|---|
| **평균 출고 소요일** | 한도 회전율에 직결 (2.3 참조) |
| **품절률** | 주문 후 품절 → 취소 → 정산 0 + 랭킹 하락 |
| **반품 환불 속도·정책** | 반품 시 현금이 묶이는 기간 |
| **세금계산서 발행** | 안 되면 부가세 2.4배 |

**공급처가 나쁘면 그 집 상품이 전부 나쁘다. 상품 수천 개를 개별로 볼 필요가 없어진다.**

### 2층 — 수요 교차검증

**위탁 구조에서는 도매 발주 = 실제 소비자 주문**이므로, 도매 판매량은 단순 인기순이 아니라 **실판매 신호**다.

| 도매 판매량 | 검색량 | 해석 |
|---|---|---|
| 높음 | 높음 | 수요 확정. 경쟁만 확인 |
| **높음** | **낮음** | **검색 아닌 피드로 팔림** → 토스·톡스토어에 유리 |
| 낮음 | 높음 | 이 상품이 답이 아닐 수 있음 |
| 낮음 | 낮음 | 제외 |

**도매 베스트 1~100위는 피할 것.** 모든 셀러가 보는 구간이라 이미 최저가 경쟁 중. **100~1,000위 구간이 사냥터** `[미검증]`.

### 3층 — 경쟁 여지

- 상위 10개 중 **리뷰 100개 미만이 3개 이상** → 신규 진입 여지 있음
- 최저가와 중앙값 갭 **15% 초과** → 이미 치킨게임, 제외

### 4층 — 마진룸 (2 시나리오)

```
마진룸(P) = P × (1 − 수수료율) − 공급가 − 배송비 − (CPC ÷ 전환율)

낙관 = 마진룸(상위10 중앙값)
비관 = 마진룸(상위10 최저가)

통과: 비관 ≥ 0  AND  낙관 ≥ 목표 순이익
```

**비관 조건이 핵심.** 최저가로 끌려가도 손해는 안 보는 상품만 통과.

### 5층 — 썸네일 (사람 손, 실제 승부처)

네이버 인기도 = **클릭수 + 찜 + 판매실적 + 리뷰수 + 최신성**.
신규 셀러는 판매실적·리뷰수가 0이다. **남은 레버는 둘뿐이다.**

| 레버 | 활용 |
|---|---|
| **CTR (썸네일)** | 클릭수 항목에 직접 반영. 신규가 즉시 쓸 수 있는 유일한 레버 |
| **최신성** | 계속 새로 등록하면 최신성 점수를 계속 받음 → 대량 등록과 맞물림 |

**"팔릴 상품을 고르는 것"보다 "같은 상품에서 이기는 것"이 더 직접적이다.** 같은 도매 상품을 20명이 판다면 팔릴 확률은 상품이 아니라 그 20명 중 내 순위가 결정한다.

**1~4층은 자동화 가능, 5층이 사람 손. 그리고 5층이 팔릴 확률을 가장 크게 움직인다.**

## 6. 등록 전략

### 6.1 등록 규모와 현금 노출은 분리된다

**위탁이라 주문이 들어와야 발주한다. 등록을 아무리 많이 해도 카드는 팔린 만큼만 나간다.**
→ **등록은 플랫폼 한도까지 최대로 해도 현금 리스크가 안 커진다.**

통제해야 할 것은 등록 수가 아니라 **동시 미결제 카드 잔액**이다.

### 6.2 네이버 판매상품비중 3% ← 대량 전략의 진짜 상한

```
판매상품비중 = 판매 발생 상품 "종류 수" ÷ 등록 상품 수 ≥ 3%
```

판매 **횟수**가 아니라 **종류 수**다. 미달 시 등록 한도가 안 늘고, **초과분은 자동 정리(삭제)**된다.

| 등록 수 | 필요한 "팔린 종류 수" |
|---|---|
| 1,000 | 30종 |
| 10,000 | 300종 |
| 20,000 | 600종 |

**판매가 분산될수록 유리하다.** 롱테일 저CPC 전략은 이 정책과 궁합이 맞고, 소수정예는 불리하다.

| 종당 평균 판매 | 월 990건 기준 판매 종수 | 유지 가능 등록 한도 |
|---|---|---|
| 종당 10건 (집중) | 99종 | 3,300개 |
| **종당 3건 (롱테일)** | **330종** | **11,000개** |

→ 주 1,000개 등록은 **초기 2~3개월간 가능**하고, 그 뒤엔 "적립"이 아니라 **"교체"**로 전환된다. 위탁은 재고가 없어 회전 비용이 0이다.

### 6.3 어뷰징 제재 — 가장 큰 리스크

**네이버는 주당 2건 이상 적발 시 '주의'** → 반복 시 '경고'(네이버플러스 스토어 노출 제외) → 누적 시 **'제한'(스토어 전체가 네이버 쇼핑에서 노출 제외)**.

**상품 하나가 아니라 스토어가 죽는다.** 주 1,000개를 올리는데 2개만 걸려도 시작된다.

**파이프라인에 필수로 넣을 검증:**

| 검증 | 이유 |
|---|---|
| **중복 상품 차단** | 도매 상품ID 기준 dedup. **"상품명만 바꾼 같은 상품"이 가장 흔한 적발 사유** |
| 카테고리 오분류 차단 | AI 매핑 신뢰도 낮으면 등록 보류. **카테고리 틀리면 노출 0** |
| 금지어 필터 | "최저가", 근거 없는 최상급 표현 |
| 등록 속도 램프업 | 실패 사례가 **하루 600개 일괄 등록**. 하루 150개씩 분산 권장 `[안전 속도 공개 데이터 없음]` |

**네이버 스토어를 여러 개 만들어 같은 상품을 뿌리는 것은 명시적 금지.** (네이버 스토어끼리의 얘기이며, 네이버↔쿠팡↔토스는 무관)

### 6.4 대량등록 실패 데이터

**하루 600개 일괄 등록 → 상품 1,000개 중 977개 노출 0 (97.7%).**
성공 셀러의 공통점은 도매 DB를 그대로 쓰지 않고 **상품명·카테고리·키워드를 가공**하는 것.

→ **1차 가공(상품명·카테고리·옵션)은 자동화로 전량, 2차 가공(썸네일·상세)은 신호 나온 것만.**

## 7. 코드에 구현할 것

### 7.1 현금 루프 (최우선)

```
[정산 입금 감지]
   ↓
① 부가세 적립분 분리        (매출액 × 약 4%)
② 완충 적립분 분리          (이익 × 30%, 목표 도달 시 0)
③ 잔액 전액 카드 선결제
   ↓
[한도 복구 확인]
   ↓
일일 발주 가능액 = (카드한도 × 0.6) − 현재 미결제잔액
   초과 시 → ① 광고 자동 일시중지  ② 신규 주문 억제(품절 처리)
```

**한도의 60%가 상한. 40%는 정산 지연·반품 급증 대비 버퍼.**

### 7.2 소싱 게이트 모듈

1층(공급처) → 2층(수요 교차) → 3층(경쟁) → 4층(마진룸 2시나리오) 순으로 통과시키는 순수 함수.
**2층 이후는 전부 상품 단위, 1층은 공급처 단위로 캐싱.**

### 7.3 중복·품질 검증

- 도매 상품ID 기준 dedup (등록 전 필수)
- 카테고리 매핑 신뢰도 임계값 미달 시 보류 큐로
- 금지어 필터
- 일일 등록 수 상한

### 7.4 대시보드 KPI

| 순위 | 지표 | 기준 |
|---|---|---|
| **1** | **CCC = 정산일 − 카드결제일** | **음수 유지** |
| **2** | 미결제 카드잔액 ÷ 한도 | **60% 이하** |
| **3** | **판매 발생 종수 ÷ 등록 수** | **3% 이상** (네이버 방어선) |
| 4 | 반품률 | 10% 이하 |
| 5 | 단계별 통과율 (노출률→클릭률→전환율) | 실측 대상 |
| 6 | 마진율 | — |

**마진율이 6순위다.** 이 구조에서는 마진이 낮아도 회전이 빠르면 이기고, 마진이 높아도 정산이 느리면 죽는다.

## 9. 미검증 가정

**이 문서의 계산은 아래 가정 위에 서 있다. 실측되면 즉시 교체할 것.**

| 항목 | 현재 값 | 상태 |
|---|---|---|
| **전환율** | 1.5~2% 가정 | **공개 데이터는 사이트 전체 세션 기준이라 광고 클릭 기준과 다름.** 가장 중요한 미검증 항목 |
| **CPC** | 70~250원 | 네이버 쇼핑검색광고 **최소 입찰가 70원은 확인**. 평균 낙찰가는 미확인 |
| 노출률 | 15% 가정 | 도매 DB 그대로 올린 경우 2.3%(977/1000)만 확인됨. 1차 가공 시 얼마나 오르는지 미확인 |
| 원가율 50% 상품의 실재 여부 | 가정 | **도매 API로 전수 확인 가능. 최우선 검증 대상** |
| 시장가 적정 구간 | 5.5~8만원 | 계산상 도출. 관여도 페널티는 정량화 못 함 |
